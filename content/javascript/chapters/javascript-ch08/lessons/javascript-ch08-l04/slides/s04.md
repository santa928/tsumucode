演習では「入力への案内」と「登録済みの題名」を別の要素に表示します。空なら案内を変えるだけで、登録済みの題名は消しません。題名があれば、案内と登録済みの表示を更新します。

前のsubmitのhandler内を、次のように分けます。statusは案内、savedは登録済みの表示先です。Formの取得とpreventDefaultは前の例と同じです。

```js {"label":"handler内の分岐", "role":"input"}
const status = document.querySelector('#status');
const saved = document.querySelector('#saved');
const title = field.value.trim();
if (title === '') {
  status.textContent = '題名を入力してください';
} else {
  status.textContent = '登録しました';
  saved.textContent = '登録済み: ' + title;
}
```

![送信時に空白を除き、空なら案内だけ、題名ありなら登録済みの表示も更新する](asset:validation-flow)

たとえば春の本を登録した後、空にして送信すると入力案内が出ますが、登録済みは春の本のままです。次に夏の本を送信すると案内も更新され、登録済みも夏の本になります。

画面内の検証は入力しやすくするためのものです。実際にサーバーへ保存するサービスでは、サーバー側でも別に検証が必要です。この演習は外部へ送信しません。
