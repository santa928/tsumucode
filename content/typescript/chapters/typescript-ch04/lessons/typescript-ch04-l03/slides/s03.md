前のaddPointを使います。originalは通常の変更可能な配列です。readonlyの引数へ渡した後も、呼出し元のoriginal.push(4)は型が通ります。readonlyは別の参照まで変更禁止にする仕組みではありません。

```ts
const original = [1, 2];
const updated = addPoint(original);
original.push(4);
```

更新後のoriginalは1,2,4、先に作ったupdatedは1,2,3です。実行時の凍結はObject.freezeなど別の仕組みです。readonlyを深い凍結として説明せず、今回の数値配列のコピーと参照の違いを確認します。

:::practice
prompt: original.push(4)でupdatedにも4が入りますか。
expectedAction: addPointが別配列を作ったのでupdatedへ4は入らない
estimatedMinutes: 1
:::
