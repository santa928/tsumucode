空値/空白で送信した案内、入力中の案内、有効な入力の送信結果を予測します。やり直しではnameとattemptedを初期化します。

演習ではsubmitの取消だけを修正します。入力欄のlabel、文字数、エラー案内が同じStateに由来するかも追いましょう。一度正しい画面が出ても、繰り返し入力・送信・やり直しが一致するとは限りません。

:::practice
prompt: messageだけを別Stateへコピーすると、何を二重に管理しますか。
expectedAction: name/attemptedから計算できる表示を二重管理し、更新漏れが起きると説明する
estimatedMinutes: 1
:::
