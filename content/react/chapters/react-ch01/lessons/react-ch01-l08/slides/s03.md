演習ではreducer.tsだけを編集します。送信actionでも「入力中」が続く理由を予測して修正します。label、submitの取消、dispatchと表示の接続は用意済みです。

空値・空白・Ada・TypeScriptで入力と送信を繰り返し、最後にやり直します。名前・送信を試したかを表すフラグから文字数と案内を導くため、派生値のStateを増やす必要はありません。

:::practice
prompt: 入力actionでattemptedを戻さなかった場合、送信後に名前を変えるとどう見えますか。
expectedAction: 新しい入力中も送信を試した後の表示が残ると予測する
estimatedMinutes: 1
:::
