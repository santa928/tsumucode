# JavaScript制作教材の接続契約

JavaScript Courseはdraftのまま、標準46 Lesson / 48 Exercise / 184 conceptSlides / 760分を維持する。Guided5 Lesson / 100分とCapstone1 Lesson / 150分を追加し、全52 Lesson / 54 Exercise（必須52・任意2） / 202 conceptSlides / 14 Chapter / 4 Phase / 推定所要時間1,010分をCourse実体へ同期する。実在学習者の実測時間を表す数字ではない。公開登録・公開承認・配信・Release Gateは後工程の対象とする。

Guidedは問題表示、回答、得点、結果、再挑戦を同じ4 Fileで積み上げ、`javascript-quiz-guided`を共有する。Capstoneはカテゴリと進捗を加えた独立作品として`javascript-quiz-capstone`を使う。6つの制作Conceptは既習の前提からread / transform / composeへつなぐ。CapstoneのGuide・Slide・Hintは局所例と設計・確認の順序を示し、完成Sourceを段階コピーしない。

Project checklist.ruleIdsとCapstone completion.requiredRuleIdsは、同Lessonで宣言済みの静的Rule / Groupまたは`interaction:scenario:checkpoint`集約要件を参照する。個別expectation履歴ID、未知checkpoint、他Lesson、重複、未定義groupは受理しない。一般IDとExerciseStep.validationRuleIdsは従来どおり静的IDのみとする。CapstoneのrequiredViewportIdsは各必須checkpointのowner Exerciseが実際に操作観測するpreviewViewportsを含む必要があり、別Exerciseだけにあるviewportを観測済みとしない。

完了画面も同じexerciseRequirementIdsからcheckpointの一意な所有者を解決する。合格snapshotとDraftの編集revision・教材revision、現在合格・完了、dirty状態の検査を維持し、参照拡張だけで古い成功を完了画面へ通さない。

採点は現在工程までのprefix、編集による失効は全Workspaceを対象とする。後工程Solutionでも以前工程の採点を満たす。編集は過去passing snapshot・初回完了日時を保持する。Reset取消は全保持し、確定Resetは当該Lesson Starter全Fileへの復元、既存Hint・判定履歴・snapshot消去と全WorkspaceのcurrentComplete失効を行う。Preview内のクイズ進行stateはSource保存とは別で、再描画やreloadにより初期化する。

主要な採点はnative button/selectを実操作したScenarioで行う。正誤、加点、結果、再挑戦、カテゴリ、進捗、Keyboard、同梱loaderのloading / failure / recoveryを観測する。importだけでデータ利用を証明したとは扱わず、未使用importと固定DOMの実負例を通す。Source全文や変数名を一致条件にせず、import aliasと状態管理の別解を受理する。

問題と2択の表示は`selector-visible`で確認する。既存の認証Snapshotから、対象の正の表示boxとvisibility、対象および全祖先のdisplay・opacityを読む。非表示、欠けた祖先・必要なCSS観測、重複ID、循環した親参照は不合格にする。この観測はhidden属性やSourceの書き方に限定せず、祖先CSSによる非表示も検出する。画面の遮蔽やviewport外の位置まで証明するものではない。

回答後は両方の選択肢がnativeの`:disabled`状態となり、同じ問題への再clickで判定・得点が変わらないことを実操作で確認する。fieldsetから継承したdisabledも受理し、個別button.disabledや特定の状態変数を必須にしない。4つのScenarioと各10操作上限を保持し、再挑戦完走のScenarioに余裕がない場合は二重回答の観測を同工程の別Scenarioへ配置する。

Guidedの練習Loaderは意図した失敗後の再試行で2問の順を入れ替える。同じ返却Array契約を保ち、全工程のrecovery checkpointで新しい先頭と2択を観測する。Guide・Brief・3 Hintでこの変化と取得データを描画する理由を示す。CapstoneのLoaderはカテゴリ選択用の元Arrayを返す従来契約を保つ。

受入検証は全6 Starter / Solution / 正負Fixture、全後工程のprefix、累積UI save / reload / 誤答 / Reset取消・確定、別保存状態への実bundle download / import / 再採点、Keyboardと失敗復帰、1280×720と390×844の実画像目視を含む。G5の実prefix採点は既存予算のwarmup3回＋測定20回・p95≤3,000msで評価する。追加Lesson manifest・JS依存閉包・catalog/indexの既存gzip予算も実buildで確認する。未実行・失敗・資源競合による中断は成功に含めない。新6 Lessonの内容hashは独立review承認を待つ。

提供questions.jsはJSON形式の同梱データを内部でArrayへ展開して返す。JSON.parseの記述・習得を学習者へ必須化せず、Guideで提供Module内部は編集不要と示す。実行するのは既存Runtime.sourceType=moduleで指定したentryFileで、HTMLのsrc参照は既存acknowledged script契約に従う。通常Starter/Solutionは不要な安全warningを出さず、学習データJSONのdownload/importを対象とする。JS作品をstandalone ZIPとして持ち出す機能は追加しない。

trusted key操作は有効なnative HTMLButtonElementのtype=buttonだけ、Enterのkeydown、Spaceの未消費keydown/keyup後に捕捉済みclickを行う。取消済み入力、disabled/fieldset、他key/element/submitへ既定activationを追加しない。独自handlerが明示clickすると、実Browserと同じ二重発火が残り、採点側だけ一回へ丸めない。

Scenarioの遅延観測は25ms間隔で、毎回新しいrequestから現時点のDOMを認証付きSnapshotとして取得する。750msの期限と未一致の失敗を維持し、Actionを再送したり、以前の観測を新しいScenarioの実行済み結果として使わない。性能予算は実5工程prefixの`tsumucode:validation`区間で比較し、clickからCompletion表示までのUI時間とtest側のpoll検知時間は別に記録する。

project＋moduleの同一Runner instanceは成功した純粋な解析artifactを1件だけ保持する。keyは全Workspaceの正規化pathと内容、session、編集revision、entry、profile、sourceTypeの完全一致で、HTML/CSSや未使用JSの変更もmissになる。保持するJSONはentryFile・graphSha256・modules・factsだけで、検証済み元guardIdentifierを組にする。request/session/revisionのWorker応答identityは保持せず、hitでも現在identityを持つローカル結果をstrict schemaで検査し、元guardを新しいruntimeKey・token・frameへ接続して実行する。Snapshot、Action、DOM、viewport、Asset、採点結果は再利用しない。keyとartifactとguardの合計1MiB以内だけを保持し、合法大型結果は保持をbypassする。prepare・stop・disposeと現在operationの異常で保持を消す。遅い旧generationの成功・失敗は後発entryを登録・消去できず、他profileの解析は毎回行う。

同一Validator instanceのproject＋module／Browser preview判定も、成功pure分析を1件だけ保持する。lookup前に、元のJS path・内容・entry・profile・sourceType・session/revision・guardが既存Analyzer request strict契約を満たすことを確認し、path aliasを正規化してhitへ合流させない。keyは解析semantics versionと全Workspaceのraw path・exact内容、解析identityの完全一致である。元の衝突確認済guardとentryFile・graphSha256・modules・factsのJSONだけを組で保持し、合計1MiB超の合法payloadは解析成功のまま保持だけbypassする。旧Worker identityを保存せず、hitの現在identity結果もstrict response契約で確認する。

Validator hitは実行・採点成功を意味しない。Ruleparse、diagnostics、fresh snapshot identity、execution/budget evidence、source file存在、current graph hash、全viewport/checkpointと全Ruleを毎回評価する。Exercise・Rules・now・context・Result・DOM・Snapshot・Action・実行証拠は保持しない。各validate開始は早期invalidも含め新generationを作り、入力/解析異常はその現世代のentryだけを消す。遅い旧成功・失敗は後発entryを登録・消去できない。通常のincompleteは純分析失敗と区別する。local／browser-console／他profileでは従来どおり毎回解析する。

編集権の自己再確認中（yielding／claiming＋revalidating）は、既存の再確認statusと同じ条件でCodeMirrorをreadOnlyへ接続する。同じdocument・selection・File別履歴と読取/コピーのfocusを保持し、所有権復帰後に入力を再開する。CodeMirrorのDOM contenteditable、aria-readonly、state.readOnlyを一致させ、onChangeの書込guardとlease取得/喪失の契約は維持する。この境界の補正は、以前の全UI入力失敗の実原因が確定したという主張ではない。

小画面ではJavaScript作品の編集・Script実行を開始せず、完成済みでも既存の「PCで演習を開く」案内とURLコピー・端末データ持出し導線を維持する。専用read-only Previewの登録有無を生成前に確認し、未対応を端末保存の読込エラーへ誤変換しない。登録済みHTML/CSSのscriptless完成Previewと保存済みSource・Snapshot・履歴・完成状態は変えない。
