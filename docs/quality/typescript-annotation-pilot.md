## 学習目標

得点を入れる変数の右に `: number` を書き、数値を受け取る約束を表せる。文字列を数値に変換する記法ではないと説明できる。このLessonでは注釈を書く練習をするが、TypeScriptの全変数に注釈が必要とは教えない。

## Slide原稿（各1画面、レイアウト前）

### 1. 変数に受け取る値の型を書く

JavaScriptでは値としての2と文字列の「2」は別でした。TypeScriptでは変数名の後ろに型を添えて、受け取る値の種類を表せます。これを**型注釈**と呼びます。

```ts
let score: number = 0;
score = 2;
console.log(score);
```

`number`は数値の型です。`score`が変数名、`: number`が型注釈、`= 0`が最初に入れる値です。Consoleの2を予測してから確認します。

### 2. 数値と文字列を取り違えると

```ts
let score: number = '2';
```

引用符で囲まれた`'2'`は文字列なので、数値の約束に合いません。引用符には一重の`'`と二重の`"`があり、どちらで囲んでも文字列です。型検査は実行前にこの違いを知らせます。`: number`を書いても文字列を数値へ変換しません。

予測: このコードのConsole出力を探す前に、どこを見直せばよいでしょう。確認: 変数に書いた型と、代入する値の型です。

### 3. 型を消して通すこととの違い

```ts
let score = 0;
score = 2;
```

注釈がなくても、最初の値から型が推論される場合があります。これは前のLessonで扱った書き方です。今回は受け取る値の約束を自分で書く練習なので、`: number`を残して数値を入れます。

型検査が通ったことと、今回の練習を終えたことは別です。`any`は型の確認を弱める型で、今回の数値という約束の代わりには使いません。型の確認を無視する指示や、値を別の型だと扱わせる書き方も今回は使いません。

### 4. 修正して、得点を表示する

```ts
let score: number = 0;
score = 2;
console.log(score);
```

最初の値を数値に直し、`score`へ2を代入します。最後の行は`score`の現在の値をConsoleへ表示します。「プレビューを更新」で型の案内が消え、2が出ることを確かめ、その後「判定する」で課題の条件を確認します。

## Exercise原稿とHint

目的: `main.ts`の`score`に数値の型注釈を残し、数値の得点2を持たせ、その値を表示する。`console.log(2)`と表示だけを固定する変更は目的を満たさない。型の約束を消したり、確認を弱めたりして通さない。初回は型エラーなので実行/採点しないことを先に説明する。

Starter:

```ts
let score: number = '2';
console.log(score);
```

3段階Hint:

1. `score`に書いた型と、右辺の値の型を見比べます。Consoleの行より前で止まっています。
2. 引用符で囲まれた値は文字列です。ここでは数値を入れる必要があります。型注釈は残します。
3. `'2'`を数値の`2`へ直します。`console.log(score)`は現在の得点を表示するので残せます。

Solution最小例は `let score: number = 2; console.log(score);`。初期化後に代入する例、1に1を足す例も意味を満たす別解。表示固定、型注釈削除、any、型assertion、診断抑制を区別する。Hint3の直接的な手掛かりは最後だけに置く。

## 正負ケースと実証の限界

`tests/fixtures/typescript-annotation-pilot.json` の11ケースを固定Compilerと元TS構文で観察する。`scripts/content/probeTypeScriptAnnotationPilot.ts` は制作者向けの試験であり、製品Validatorではない。このCLIは学習者コードを実行せず、汎用の型習得判定や安全性を証明しない。

| ケース           | Compiler | 次の採点契約で区別すること           |
| ---------------- | -------- | ------------------------------------ |
| starter          | 型誤り   | 未実行・未採点のまま修正を案内       |
| solution         | 成功     | number注釈と得点2、変数の表示        |
| alternative      | 成功     | 正しい別解を許容                     |
| inference-only   | 成功     | このLessonで必要な注釈がない         |
| any-escape       | 成功     | 数値の約束が弱められている           |
| double-assertion | 成功     | 注釈だけはあるが値の型確認を迂回     |
| suppressed       | 成功     | Compiler診断を抑制している           |
| output-only      | 成功     | 得点は0のまま、表示だけ2に固定       |
| union-escape     | 成功     | 数値と文字列の両方を受け取れてしまう |
| nocheck-escape   | 成功     | ファイル全体の型検査を抑制している   |
| wrong-value      | 成功     | 数値だが課題の得点と違う             |

構文観察ではトップレベルの単一`score`だけを対象にする。型の別名、複数宣言、scope/shadowing、import、generic、コメント指示の正確な有効範囲は未対応。コメントらしい文字列と実コメントはscannerで分けるが、全診断抑制の検出保証ではない。製品接続にはWorkerの有限契約、check結果と元TS hashの結合、型関係検査の一般化、変数と出力の対応、実Runnerの動作採点が必要。固定表示と本当の得点をこの観察だけで区別できないことを残件として明示する。

型関係の試作では固定fixtureの末尾に`export { score };`を加え、別の信頼側`probe.ts`から変数の型を参照する。数値2の代入が通り、文字列「2」の代入だけが指定位置（probe.ts 3行7列）の2322になることを個別に確かめる。任意のエラーを負例成功と扱わず、診断が1件で位置とcodeが一致する場合に限定する。型だけを調べるため実行はしない。任意sourceへのexport追記や予約名/パス、scope、moduleの変更は製品契約として未確定で、この方法をそのまま製品へ接続しない。

11ケースの実測ではanyとnumber/string unionは文字列を受け取るため負例に失敗した。型推論は正負の代入を満たすが、このLesson固有の明示注釈条件を別に検査する必要がある。assertionと診断抑制は正負の代入を満たしてしまうので構文条件が別途必要。学習者fileのts-nocheckは別fileのprobe診断を消さなかったが、元コードの正しさの証拠にはならない。

2026-09-29のDocker検証では、固定Compilerによる11ケースの状態と構文観察、実行可能な10ケース各2回の正負代入検査が一致した。solution、inference-only、any-escapeは生成JSも完全一致し、消去後のコードだけでは今回の型注釈目標を区別できないことを確認した。対象Lint、既存`npm run typecheck`も成功。再現はプロジェクトDocker内で`./node_modules/.bin/tsx scripts/content/probeTypeScriptAnnotationPilot.ts`を実行する。

実Chromiumでは`tests/e2e/typescript-compiler-worker.spec.ts`の「型注釈試作」1件で11原文を実Compiler Worker→既存隔離Runnerへ渡し、14.2秒で成功した。Starterは型誤り2322でConsole空、wrong-valueは3、それ以外の9ケースは2を表示した。特に文字列「2」と数値2はConsoleの表示が同じになるので、表示だけで型の目標を評価できない。型検査用にexport/probeを追加したコピーは実行せず、fixtureの原文だけを実行した。観察JSONをテスト添付へ保存。これは実行基盤と観察の証拠であり、11ケースを製品採点で正しく判定できた証拠ではない。製品srcは不変なので保存/UI全体の通し検証は繰り返していない。
